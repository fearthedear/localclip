# Platform investigation — 21 October 2026

Primary documentation checked while building this MVP:

1. [Android 10 privacy changes: limited access to clipboard data](https://developer.android.com/about/versions/10/privacy/changes#clipboard-data). Apps without input focus, other than the default input method, cannot read clipboard data. A foreground service does not provide input focus. This restriction also affects clipboard listeners. The ordinary-app MVP therefore provides Share, selected-text processing, and a focused Send action. Version 0.2.0 keeps the user's existing keyboard and provides no replacement IME. The default-IME exception is documented but is not used in this Gboard-compatible workflow.
2. [ClipboardManager API](https://developer.android.com/reference/android/content/ClipboardManager). Reading and writing are distinct operations. Background writing through the running connection service was verified on Android API 34 and API 37 emulators, with a different app in focus. This is not a physical Pixel 11 Pro XL certification.
3. [Secure clipboard handling](https://developer.android.com/privacy-and-security/risks/secure-clipboard-handling). The source application can mark sensitive content. Android may display clipboard-read notifications/previews and may clear clipboard contents automatically. LocalClip skips marked content; it does not bypass OS privacy controls or promise that a copied clip will remain indefinitely.
4. [Foreground service types: connected device](https://developer.android.com/develop/background-work/services/fgs/service-types#connected-device). Persistent peer-device networking is implemented as a user-started `connectedDevice` foreground service, with `FOREGROUND_SERVICE_CONNECTED_DEVICE` and the documented `CHANGE_NETWORK_STATE` manifest prerequisite. It does not change the network configuration in app code. Notification permission is requested on Android 13+. No blanket battery exemption is requested.
5. [Android local network permission](https://developer.android.com/privacy-and-security/local-network-permission). This artifact compiles/targets API 36 because that SDK is installed. The current documentation applies the new `ACCESS_LOCAL_NETWORK` runtime requirement to apps targeting API 37+. Do not retarget to 37 without implementing and testing that permission flow. The supplied target-36 build was tested on an Android 17/API 37 emulator; the user's physical Pixel OS remains unverified by these automated tests.
6. [Apple NSPasteboard access behavior](https://developer.apple.com/documentation/appkit/nspasteboard/accessbehavior-swift.enum). Recent macOS releases can ask before programmatic pasteboard access. The user must permit access for background polling to work. The app cannot grant itself the Always Allow setting. Local network access may also require an OS prompt. No Accessibility permission or synthetic paste keystrokes are used.

## Explicitly unverified

The physical Pixel 11 Pro XL and its installed Android release; API 35/36 runtime behavior; phone screen-lock behavior on physical hardware; long idle/Doze, battery saver, reboot, Wi-Fi changes, AP isolation, macOS firewall prompts and Gatekeeper on another machine; Tailscale transport/ACLs/DERP; destination-app image compatibility; copy/paste between every pair of source/destination apps; Intel execution; distribution notarization; cryptographic security audit.

A foreground service improves connection lifetime but does not guarantee it. With Gboard selected, the optional ADB shell helper provides automatic background copies. Its API 37 text/image path was exercised with Gboard selected and a separate app in front. Without the helper, use Share or the focused Send action. Root is not required. See [helper implementation and setup](ADB-CLIPBOARD.md).
